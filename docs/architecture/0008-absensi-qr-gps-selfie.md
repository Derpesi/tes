# ADR-0008: Absensi QR + GPS + Selfie (Online-Only)

- Status: **Disetujui** (diimplementasikan dan diuji pada Fase 7)
- Tanggal: 2026-11-21

## Konteks
Karyawan dengan penempatan AKTIF perlu absen masuk/pulang di lokasi rekanan. Kebutuhan: validasi di backend (bukan UI), shift termasuk lintas tengah malam, hari libur, perangkat terdaftar, tinjauan manusia atas kasus ambigu, koreksi bernomor, retensi selfie, dan rekap. Aturan keras: online-only (tanpa absensi offline), QR statis hanya pengenal titik, tanpa face recognition otomatis, selfie hanya untuk petugas berwenang, waktu dari server.

## Keputusan
1. **Titik absensi** (`attendance_points`): satu titik aktif per lokasi rekanan (indeks unik parsial); `public_code` UUID acak = isi QR (`<APP_BASE_URL>/absen?t=<kode>`). Kode dapat diganti (kode lama seketika tidak dikenali) dan titik dapat dinonaktifkan. PDF poster QR dibangkitkan sesuai permintaan (`qrcode` + `pdf-lib`), tidak disimpan, pencetakan diaudit.
2. **Shift, jadwal, libur**: `shift_patterns` (FIXED/FLEXIBLE, toleransi masuk/pulang, `crosses_midnight` dijaga CHECK), `work_schedules` per penempatan (hari kerja ISO 1–7, periode; tabrakan hari+periode ditolak aplikasi), `holidays` (NASIONAL/PERUSAHAAN/LOKASI), override toleransi per lokasi. Dikelola lewat izin `placement.*` (PayAbs memegang `placement.update`).
3. **Tanggal-shift = tanggal MULAI shift**. Penentuan shift adalah fungsi murni berjam-disuntikkan (`shift.ts`), diuji tabel kasus: jendela MASUK `[mulai − toleransi awal, selesai]`, jendela PULANG `[mulai, selesai + toleransi terlambat]`; bila beberapa kandidat, dipilih yang sudah dimulai paling akhir.
4. **Rekaman** (`attendance_records`): setiap percobaan yang sampai ke penilaian disimpan, termasuk `DITOLAK`. `occurred_at` = waktu **server** (jam disuntikkan di tes); waktu klien hanya dibandingkan (selisih > 5 menit → penanda). Unik per (orang, titik, jenis, tanggal-shift) untuk status non-DITOLAK; **kunci idempotensi** unik per orang (pengulangan mengembalikan hasil awal, 200).
5. **Pipeline** (urutan tetap): karyawan aktif (403) → titik dikenal (404) dan aktif (409) → penempatan AKTIF di lokasi titik + kontrak AKTIF (403) → jadwal/libur/tanggal-shift → selfie wajib JPEG ≤ 300 KB (DITOLAK) → geofence Haversine ≤ radius (DITOLAK `LUAR_RADIUS`) → duplikat (DITOLAK) → perangkat (DITOLAK bila ditolak petugas) → skor anomali. Hasil: `VALID`, `PERLU_VERIFIKASI` (GPS buruk/hilang, penanda berskor, perangkat baru, tanpa jadwal, hari libur, pulang tanpa masuk), atau `DITOLAK`. Terlambat/pulang cepat = penanda skor 0 (tetap VALID).
6. **Perangkat** (`device_registrations`): id acak klien disimpan sebagai HMAC. Perangkat pertama disetujui otomatis; tambahan → `PERLU_VERIFIKASI` (+ penanda); satu perangkat > 3 akun → penanda. Persetujuan perangkat lewat putusan tinjauan.
7. **Anomali** (`anomali.ts`): lompatan lokasi (> 150 km/jam), koordinat identik ≥ 5×, akurasi > 100 m, waktu klien menyimpang > 5 menit, banyak akun satu perangkat. Ambang adalah konstanta berdokumen (A-34), bukan data regulasi.
8. **Selfie**: hanya dari kamera (`getUserMedia`, tanpa input berkas); server memeriksa magic bytes JPEG dan ukuran, **mengenkripsi** (AES-GCM, AAD = kunci objek), menyimpan SHA-256 dan `purge_after`. Server **tidak dapat membuktikan** foto berasal dari kamera. **Tanpa face recognition.** Foto hanya lewat API (`selfie.view`: Mgr Ops, PayAbs, PayInt per A-09), **setiap akses diaudit sebelum byte dikirim** (gagal-aman), `no-store`.
9. **Retensi**: `documentSettings.selfieRetentionDays` per perusahaan (7–3650, bawaan 90, dibaca fungsi `retensi_selfie_hari`). Pekerjaan harian (`SelfieService.purge`, jam disuntikkan) menghapus objek yang lewat batas kecuali **legal hold** (Mgr Ops, alasan wajib, diaudit); satu objek yang gagal tidak menghentikan yang lain. Baris rekaman tetap (bahan audit).
10. **Tinjauan dua langkah** (`attendance_reviews`, hanya-tambah): PayAbs/PayInt memeriksa (`attendance_anomaly.review`), Mgr Ops memutuskan (`attendance_anomaly.approve`); orang berbeda (aplikasi + trigger database). Rekaman asli tidak diubah; `attendance_effective` memakai putusan. Putusan dapat sekaligus menyetujui/menolak perangkat.
11. **Koreksi** (`attendance_adjustments`): nomor `KOR/<tahun>/<urut 5 digit>`, diajukan PayAbs/PayInt, diputuskan Mgr Ops, penyetuju ≠ pembuat (aplikasi + CHECK), alasan wajib, tidak dapat diubah setelah diputuskan; rekaman asli tidak berubah; hanya koreksi DISETUJUI yang dipakai rekap.
12. **Rekap** per orang-hari dari rekaman efektif (rentang ≤ 93 hari, keyset) dan **ekspor CSV** (≤ 10.000 baris, BOM UTF-8, sel berawalan `= + - @ TAB CR` dinetralkan, diaudit per perusahaan). Hari tanpa rekaman/koreksi belum ditampilkan (Fase 8). Tanpa perhitungan gaji.
13. **RLS**: semua tabel ber-`company_id` + `enable_tenant_rls`. Kebijakan baca-milik untuk member (rekaman, koreksi, perangkat, penanda, jadwal/shift/libur penempatannya) dan kebijakan tulis sempit untuk alur absen. Dua kebijakan SELECT sangat sempit hanya terbuka bila kode server menyetel variabel transaksi: `app.titik_kode` (mengenali titik dari kode QR) dan `app.perangkat_hash` (menghitung akun per perangkat).
14. **Izin "salah satu"**: `RequirePermission(izin, ...alternatif)`. Dipakai agar daftar baca terbuka bagi pelaksana tindakan (antrean tinjauan, koreksi, titik absensi) tanpa mengubah matriks `rbac.md`; izin aksi tetap tunggal.
15. **Web**: `/absen` (member; izin kamera/lokasi hanya pada halaman ini lewat `Permissions-Policy`; CSP `img-src blob:` untuk pratinjau), `/saya/absensi`, `/staff/titik-absensi|jadwal|tinjauan-absensi|koreksi-absensi|rekap-absensi`. Login member meneruskan `returnTo` agar QR yang dipindai sebelum login kembali ke `/absen`.

## Operasi
Purge selfie berjalan di proses API sekali sehari (mati saat `NODE_ENV=test`); tanpa serialisasi antar-instance selain `FOR UPDATE SKIP LOCKED` dan idempotensi. Kegagalan hapus objek dicatat di log (tanpa kunci objek) dan dihitung. Retensi final wajib ditinjau terhadap UU Pelindungan Data Pribadi.

## Konsekuensi dan keterbatasan
Absensi PWA **tidak membuktikan kehadiran mutlak**: QR dapat difoto, GPS dapat dipalsukan (mock location tidak terdeteksi andal), kamera langsung tidak dapat dibuktikan server. Kontrol berlapis hanya menurunkan risiko dan menyerahkan kasus ambigu ke tinjauan manusia. Kualifikator sel matriks (PayAbs "U(shift)", penampil selfie "rekanan/internal") belum ditegakkan. Partisi bulanan `attendance_records` ditunda ke Fase 10 (uji beban). Selfie dialirkan lewat API (belum ada URL bertanda tangan sampai driver S3 ada). Ekspor hanya CSV; xlsx/PDF dan rekap payroll di Fase 8. Rekap belum menurunkan hari tanpa absen dari jadwal. Pemindai virus dan rotasi kunci enkripsi masih terbuka.
